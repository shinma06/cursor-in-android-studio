## 1. 方針・優先度

1. P0: 権限の誤認を防ぎ、既知の Worktree/復元不一致を扱う。Cursorと同じラベルを付けるだけで保護を保証しない。
2. P1: 日常操作を少ないCLI依存で改善する。コピー/送信キー → 会話保存 → 状態・レビュー・キュー → コンテキストの順。
3. P2: 未確認CLI機能の調査と、表示・会話管理の拡張。未確認のまま実装を約束しない。
4. 低優先のIDE共通機能は標準機能へ委譲し、差分ゼロを目的に複製しない。

優先度・規模・順序の判断は **[仮説]**。S=単一UI中心、M=複数層、L=永続化/状態管理を含む目安であり日数の確約ではない。
対応順は推奨順。開始を阻む依存関係と区別する。P0を先行し、未確認機能の調査待ちで独立したUI改善を止めない。

## 3. 作業単位と受入条件

以下は登録時点のスコープ。着手後のチェック状態と変更理由は各 Issue で管理する。

### UX-01: 権限・sandbox の誤認防止と Worktree 復元の整合性 ([#20](https://github.com/shinma06/cursor-agent-plugin/issues/20))

根拠: UI-26, UI-31, UI-45, UI-46 / 既存要件: F-22〜24, F-30/31, F-40〜44, F-52

Ask Every Time の名称から事前承認を期待する誤認、および分離 Worktree に対してプロジェクト側 checkpoint を使う既知の不一致を先に解消する。

- headless CLI の既存検証を根拠に、編集が即時適用されること・Revert が事後復元であることを入力付近と設定に明示する
- 権限、sandbox、Worktree の現在値を入力付近で確認できる。保存済みの設定を移行しても権限を自動で緩めない
- Cursor の4択を機械的にコピーしない。CLIとの対応表と未対応の保護項目を記録する。保護を保証できない設定スイッチを置かない
- Worktree ISOLATED 時の checkpoint 方針を決定し実装する。初期候補は復元を無効化して理由を表示する方式。保存先の対応方式を採る場合は対象パスを実データで確認する
- Worktree切替後も古い復元ボタンが誤ったルートへ復元しない。既存 Revert の新しい変更を上書きしない保護を維持する
- 設定移行・対象ルート判定の単体テスト、MV-024/025/026/027/030 と新しい表示確認を手動マトリクスに反映する

スコープ境界: 新しい allowlist/ネットワーク/個別保護の制御実装は UX-06 の検証結果待ち。今回の Issue 作成時点では機能実装未着手。

### UX-02: 応答コピー・送信キー選択・設定とモデル状態の導線 ([#21](https://github.com/shinma06/cursor-agent-plugin/issues/21))

根拠: UI-04, UI-11, UI-15, UI-17 / 既存要件: F-01, F-05, F-21

CLI の新機能に依存せず、毎回使う入力と応答の操作を改善できる。

- 応答ごとに Copy message を追加し、Markdown 原文をそのままコピーできる。空応答時の扱いとコピー完了表示を定義する
- Enter送信/改行修飾キー方式と、Cmd+Enter（macOS）/Ctrl+Enter（その他）送信方式を選択・保存できる
- IME変換確定、Shift+Enter、mention候補決定で誤送信しない。実行中のEnterも重複送信しない
- Agentタブから Settings → Tools → Cursor Agent を開ける
- モデル取得の Loading/取得失敗/空一覧/選択済みを区別し再試行できる。根拠のないプラン制限推定を表示しない
- MV-010/011/016 を拡張して実機QAを記録し、設定保存・入力判断の必要な単体テストを通す

スコープ境界: Cursor のアップグレード導線の複製、ブラウザ実装、会話全体のエクスポートは含めない。

### UX-03: 会話本文の永続化・履歴再表示・検索・Markdown出力 ([#22](https://github.com/shinma06/cursor-agent-plugin/issues/22))

根拠: UI-13, UI-14 / 既存要件: F-03, F-50

既存履歴はメタデータのみで、再開すると本文が消える。CLIの過去本文取得に依存せず今後の会話をプラグイン側で保存する。

- 会話・ターン・メッセージの安定ID、順序、状態、保存形式バージョンと移行方針を定義する
- 今後受信するユーザー/応答/ツール要約/エラーをプロジェクト単位で保存し、再起動後に再表示できる。保存失敗・破損で他会話を失わない
- 旧メタデータだけの会話は本文なしと明示する。CLIから取得できない過去本文を補完・生成しない
- 履歴に明示的な検索欄を追加し、空結果を表示する。検索対象（タイトル/本文）を明記する
- ユーザー操作で保存先を選び Markdown transcript を出力する。自動アップロードはしない。元プロンプトと注入コンテキストを区別し、不要な認証情報・CLI環境変数を保存しない
- 保存量/保持期間/削除方針を定義し、移行・破損・再開・出力の単体テストと手動再起動QAを記録する

スコープ境界: 過去の Cursor/CLI 会話の遡及取得、会話分岐、アーカイブは別フェーズ。

### UX-04: 追加入力キュー・変更一覧・状態時間・通知の整理 ([#23](https://github.com/shinma06/cursor-agent-plugin/issues/23))

根拠: UI-09, UI-10, UI-19, UI-32, UI-37, UI-41 / 既存要件: F-01, F-30〜32, 通知

長いターンで何が進行し何が変更されたかを追いやすくし、次の指示を準備できるようにする。

- 段階A: Preparing/Running/Thinking/ツール/Completed/Stopped/Error を区別し、経過時間を表示する。計測できない思考時間を推定値で断定しない
- 段階A: ツール詳細の折畳みと通知抑制を追加する。承認待ちイベント未対応なら承認待ち通知を捏造しない。完了/失敗と単なるツール開始を区別する
- 段階B: ターン/セッションの変更一覧からファイル差分へ移動できる。事後diff/Revertの意味を維持し、古いRevert拒否・Worktree安全性を回帰確認する
- 段階C: 実行中も追加入力を編集・キュー登録でき、完了後に同一セッションへ順番に送る。既定は現行動作を維持する移行方針を定義する
- 段階C: Stop/失敗/New Chat/履歴切替/プロジェクト破棄時のキュー扱いを明示し、意図しない自動送信や別会話への流入、二重プロセス起動を防ぐ
- キュー状態遷移・順序・停止競合をテストする。UIは MV-001/002/015/020〜030 を拡張し、未実装段階をチェック済みにしない

スコープ境界: 実行中プロセスへのライブ割込み、Cursor固有の思考情報・承認プロトコルの推測実装、事前Applyゲートは含めない。

### UX-05: Add to Chat と明示的なコンテキスト表示・mention導線の改善 ([#24](https://github.com/shinma06/cursor-agent-plugin/issues/24))

根拠: UI-05, UI-34 / 既存要件: F-10〜16

自動注入されるコンテキストを利用者が把握できるようにし、選択コードを明示的に追加する。

- エディターの選択範囲を Add to Chat で追加し、対象ファイル/範囲が入力欄付近で確認できる
- 自動コンテキストと明示追加を区別し、重複注入と意図しない古い選択の送信を防ぐ
- 削除・変更できるコンテキスト表示を追加する。チップ化は表示と内部データの対応を維持し、文字列編集で壊れない設計を選ぶ
- ファイル/フォルダ/Branch/Terminal/Docs/Web の対応範囲と未設定時の説明を維持する。Cursor候補未確認のものを同等実装と表記しない
- #5 の既存QAを再利用し、大規模候補・IME・キーボード・Terminalなしの確認を手動マトリクスに記録する

スコープ境界: Quick Edit/Terminal内編集、Cursor独自インデックスの再現は含めない。

### UX-06: 未確認UI・CLI能力の調査ゲート（Debug/Multitask/権限/分岐等） ([#25](https://github.com/shinma06/cursor-agent-plugin/issues/25))

根拠: UI-03, UI-05〜08, UI-12, UI-15, UI-20, UI-22〜31, UI-35, UI-42〜46 / 既存要件: F-17, F-20, F-22〜24, F-52, F-60〜62, F-70/71, 要件§6.9

UIに存在する機能を根拠なくCLIで保証しない。実装可能性とスコープを確定してから追加実装Issueを作る。

- Cursorバージョン・表示プラン条件を記録し、@/Skills/Customize/Worktree/承認/エラー/復元の未確認画面を閲覧可能な範囲で追記する。入力が必要なら未確認として残す
- Debug/Multitask/Skills/分岐/割込みを非対話CLIの可否・必要イベント・制約別に整理する。名称からフラグを推測しない
- Run Mode4択、network/command/MCP/domain allowlist、個別保護、Web Search/Fetch、認証待ちについてUIとCLIの対応を調べる。設定ファイルを変更する前に適用範囲と権限を確認する
- CLIの既存ログ/fixture/公式資料を優先する。新しい実行検証が必要なら隔離したテスト環境と許可された操作範囲を用い、証跡とバージョンを記録する
- #10の画像・音声を参照し、アイコンの存在だけで対応判定を覆さない。アカウント/Privacy設定の共有やAgent統計の算出可否も未確認として管理する
- 各項目を 対応確認/非対応/未確認 に分類し、対応確認だけを実装Issueへ分割する。未確認は理由と次の必要証跡を残す。非対応はスコープ決定を記録する

スコープ境界: このIssue作成は実行・編集・送信・設定変更の許可ではない。未検証の外部仕様を断定しない。

### UX-07: 会話表示・アーカイブ・複数タブなどの拡張候補を段階取り込み ([#26](https://github.com/shinma06/cursor-agent-plugin/issues/26))

根拠: UI-01, UI-02, UI-12, UI-14, UI-16, UI-18, UI-20〜23, UI-33, UI-35〜44 / 既存要件: F-03, F-05, F-21, F-50, 要件§6.9/§8

安全性と日常操作を揃えた後に、利用頻度・必要性を見て表示と会話管理を拡張する。

- まず文字サイズ・コード折返し・新規会話の既定モデルと現在モデルの分離を扱う。IDEアクセシビリティ/テーマを尊重する
- UX-03を基にアーカイブ/復元を追加候補とし、次に複数会話タブ・切替を検討する。閉じる/置換時の未送信入力と実行中プロセスの扱いを決める
- 会話分岐・割込み・一般補完・Skills/Customize統合・アカウント/診断/統計の導線はUX-06の結果に従って採否を個別決定する
- 完了音、レビュー操作配置、完了時整形を個別に採否決定する。自動整形がRevertの比較内容を変える点を検証し、既定で新しい自動編集を有効にしない
- タイトルバー/ステータスバー/差分配色は原則IDE標準に委譲する。専用ブラウザ・Quick Edit/Terminal内編集はスコープ審査し、自動的に実装対象にしない
- 各候補の採用/見送り理由、分割先Issue、手動QAを記録する。採用項目が未完了なら本Issueを完了扱いにしない

スコープ境界: 全候補を一度に実装する約束ではない。P1完了前の大規模なUI置換は行わない。

## 5. 検証と完了の区別

- 今回は文書化とIssue登録のみ。新しいCursor/CLI実行検証や機能実装には着手しない。
- UIの存在は閲覧証跡、CLIの能力はバージョン付きの資料/実測、プラグインの対応はコード/テスト/実機QAの別々の証拠で判断する。
- 既存機能のMV番号を再利用し、新機能の手動確認は実装時に番号・対象ブランチ・手順・期待結果を確定する。未実装機能に架空のpass行を作らない。
- 状態は 未着手 → 着手中（claimコメント）→ コード完了・QA待ち → 完了。調査待ちには必要な証拠を記載し、コード完了だけでUI受入条件をチェックしない。
- 必要なロジックテストと毎push前の `./gradlew test` を実施する。ビルド/パッケージ変更なら `buildPlugin` も実施する。
- CLI動作を変える案は対応証拠と移行方針を先に記録する。新しい実行・送信・設定変更を要する調査は、許可されたテスト環境と範囲が前提。
