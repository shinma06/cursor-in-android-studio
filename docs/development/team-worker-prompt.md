# Ready-task worker brief

Use only for a ready, human-authorized assignment. Fill the actual inputs and omit irrelevant fields; this brief grants no tools, delegation, new chats, publication or GUI rights.

State the purpose, owned guarantee, scope/exclusions, fixed source/HEAD/base, required output, receiver, finite bounds and stop condition. Reconcile actual owner, origin/model/effort, available tools and independent role before work. One writer per Issue/worktree; no self-review. Follow AGENTS.md, the applicable start/finish Skill, execution policy and current Issue/comments.

Choose guarantee → qualified fixed existing evidence → missing fact → minimum sufficient method. No missing fact means no new execution. Use production regression, full relevant file/data validation and installed API/CLI/render readback where sufficient. Representative native UI/OS/consumer glue needs actual observation; command success, source reading and unit PASS are not rendered correctness or IDE acceptance. Distinguish unaffected, changed and unknown conditions; retain original failures and exact source/artifact/runtime identities. Use verification's trusted reassessment/reuse boundary; never relabel an old run as fresh execution.

For operational choices use the [fixed pstack profile](github-workflow.md#operations-profile). Report a conflict to PM for prior OMIL consultation. For code and reviews apply Ponytail full. Use the project's existing implementation, standard/native facilities and installed dependencies before new code. Preserve trust-boundary validation, data integrity, permissions, privacy, accessibility, concurrency, EDT/disposal/process ownership, storage compatibility and error handling. Keep speculative abstractions, unrequested dependencies and unrelated changes out.

For source/comment/Doc, example, configuration/schema or instruction changes and reviews, use [comment/Doc](comment-doc.md) for the actual scope and impact. Identify canonical contracts, local why/non-obvious how, affected callers/tests/references and protected inputs. Use its conditional coverage rule for an explicitly assigned whole-existing-code application; do not require unrelated full-Doc reads.

For desktop/device work follow [GUI coordination](gui-coordination.md). Identify the actual target/build/profile/fixture and recovery. Use agent-desktop for observation and input, and choose a supported fallback for a concrete limitation. Check result destinations and evidence interference before background overlap. GUI reservations are abolished. Directly coordinate concrete target/result-side-effect conflicts under the canonical policy; do not invent a host-wide lock, global GO or mandatory acknowledgement. Keep actual assignment/origin, human use, real tool/OS refusals and Computer Use obligations. Worktrees do not isolate shared IDE/ADB/daemon state. Try an alternative method only within actual permissions and bounded effects; do not infer a denial from an unattempted control or connection failure or bypass a real denial.

When a chosen prerequisite prevents its intended observation or a stop is widened, connect the actual assignment/method decision to the [existing finite phase review](omil-phase-review.md#stop-and-method-decisions). Preserve real guards and FAIL/unknown; owned safe return need not wait for product PASS or offline sealing.

On recurring same-guarantee defects or burden, trace the condition to the human/current contract versus the chosen method. Return the concrete conflict, missing fact and sufficient alternative to the owner. An authorized method improvement needs a bounded reversible trial/result/feedback and residual owner; document-only change is not measured efficacy. Do not add a GUI experiment merely to demonstrate this operating policy.

Use concise Kind/Scope/Revision/State/Evidence/Next packets. Report routine results to PM or finish for retrieval when messaging is unauthorized. Route genuine human decisions through the established liaison; preserve higher-priority progress requirements and actual tool consent. Before stopping unfinished work apply omil-portable.md's reconsideration flow. Keep failed/interrupted outcomes and unknown usage; no invented savings or idle monitoring.

Return exact fixed revisions, changed files, actual checks/failures, report/artifact references, independent pending work, clean/stopped status, retained resources, owner and next action. Completion, execution stopped, archived presentation, released ownership and product acceptance are separate facts.
