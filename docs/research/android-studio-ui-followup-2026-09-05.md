## 確認範囲

初回のCursor調査におけるプラグイン対応状況はコード確認のみだった。ユーザーの追加依頼を受け、起動済みAndroid Studioの **Cursor Agentを実際に操作**し、設定画面・インストール済みプラグイン一覧へ移動して確認した。

- 方法: CUAによるアクセシビリティ情報（AX）とスクリーンショットの目視。画像ファイル・生のAXログは保存しておらず、以下は観測文言の転記。
- 対象: macOS、プロジェクト `cursor-agent-plugin`、Cursor Agent `0.1.0-SNAPSHOT`、提供者 `SelfRegi`、状態 `Enabled`。
- インストール済みバイナリのコミットSHA、正確なIDE製品リリース名は `[要検証]`。Plugins画面のAndroid等の版表記は `261.26222.65.2614.16204760`。checkoutのブランチ表示でプラグインの版を推定しない。
- プロンプト入力・送信、Agent実行、ファイル編集、設定保存、モデル/モード/権限変更はしていない。設定ページではApplyが無効のまま、Escapeで閉じた。
- 操作中、`noWindowsAvailable`、ScreenCaptureKit `-3811`、画面変更による再取得要求が断続的に発生した。ユーザーにウィンドウを復帰してもらい、パネル表示は再確認できたが、メニュー展開操作は再び取得エラーになった。これは**操作ツール側の取得失敗**であり、プラグインのクリック不具合と断定しない。

## 再確認の順序

1. 対象のインストール済みビルドとIDE版を特定する。特定できない旧SNAPSHOTを現行ソースの不具合判定に使わない。
2. 安定して操作できる環境でモデル/モード/⋯メニューを開き、値を変更せず閉じる。完全名・検索・スクロール・Escapeを確認する。
3. 入力/mention確認では未送信の一時入力だけを使い、元に戻す。送信・実行・設定変更を伴う既存QAは閲覧確認と分けて対象範囲を確認する。

今回の結果は、プラグイン全体の実機QA合格を意味しない。
