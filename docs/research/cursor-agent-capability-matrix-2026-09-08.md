## 読み方

- 主対象 **IDE** はclassic Agent sidepane。**共通**は公式Agent一般の記述で、全build/契約での実測を意味しない。**AW**はAgents Window、**Cloud/Web**は別環境。AW限定機能をIDEの必須不足にしない。
- **公式**、**installed help**、**過去live実測**、**未検証の設計案**を分ける。今回は資料/source/helpとACP initialize・project限定read-only session/listを確認し、GUI、モデル推論、画像送信、login/update、MCP起動、worker/persist開始は行っていない。
- インストール情報: Cursor **3.19.13**（Info.plist）、CLI **2026.09.02-c22c1a3**（version/help）。これで公式記事にある全機能の導入/利用権限を証明したとは扱わない。IDE changelog先頭は9/2、CLIは8/26の掲載で、build番号とは別。
- 実装比較は main **c01af25b51e1d10aa389777d1cc20b67807b4cc9** / develop **5ee7b27ae9a4d6243b7e7e3c2122b7d7c44f38fe**。表の「main／develop」はコード上の状態。実装リンクは固定develop。GUI状態は[確認一覧](../verification/current.md)と[QA運用](../verification/README.md)が正本。
- 方式Bは `agent -p --output-format stream-json` の非TTY subprocess。**自前UI可**はplugin側実装案、**公開**は資料/help上の経路あり、**未確認**はこの方式/installed環境での実証なし。機能不存在や永久非対応を意味しない。

## 今回の訂正と着手順

画像は[headless資料](https://cursor.com/docs/cli/headless)にprompt内path読取経路がある。helpに`--image`がないだけでは非対応と断定できない。まず #10 の識別画像spike、Skills #117 / Subagents #118 / streaming #116 は公開経路と取得eventを実証する。名前取得 #66 は方式Bの機械可読取得契約が未確認で、ACPのsession/listはproject限定で応答を確認したが対象履歴0件でtitle実値を得ていない。ユーザー指定のNew Agent維持/保留を続ける。

既存の即時編集実測は維持する。公式[headless](https://cursor.com/docs/cli/headless)のforce説明と[Using CLI](https://cursor.com/docs/cli/using)・[Permissions](https://cursor.com/docs/cli/reference/permissions)・installed helpのwrite説明には不整合がある。今回の資料比較だけで事前承認を保証せず、事後Diff/Revertを維持する。

プラグインだけで進められるのは #41コピー、#97送信キー、#43モデル取得状態、#44本文保存→#45検索/export、#98経過/折畳み/通知、#47変更一覧、#48逐次queue、#24明示context、#28診断。API能力調査の全完了を待たせない。

### ACPの限定実測（2026-09-08）

CLI `2026.09.02-c22c1a3` の `agent acp` にinitializeを送り、protocolVersion 1、`loadSession: true`、`promptCapabilities.image: true` / `audio: false` / `embeddedContext: false`、`sessionCapabilities.list: {}` の広告を取得した。続けて現在projectのcwdに絞ったread-only `session/list` は `sessions: []`、nextCursorなしを返した。認証・session/new・session/load・promptは送信せず、自分が起動したprocessだけを終了した。

[ACP v1 Session List](https://agentclientprotocol.com/protocol/v1/session-list)にはcwd filter、任意title、ページ送り、`session_info_update`によるtitle更新通知がある。この通知はclientからrenameする要求ではない。今回の結果は起動・capability広告・空一覧応答の確認であり、title実値、print側chatIdとの互換、改名同期、本文の取得、画像の読取り成功、質問/承認の往復は未検証。#115で別transportとして比較し、#66のNew Agent維持/保留は継続する。公開文書には生ログやローカル環境識別子を含めない。
