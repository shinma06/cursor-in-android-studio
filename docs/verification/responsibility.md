# 製品の保証と最小の十分な検証

既存・将来の検証で「保証 → 固定した既存証拠 → 不足事実 → 必要な精度と最小の実行可能方法」の順に決める。旧レシピの秒数・操作回数・同run・毎CaseのGUI反復だけを維持理由にしない。原Case・人間の明示条件・Computer Useの実施義務・失敗・未解放所有は保持し、有効契約の変更は独立レビューを経る。規約だけで過去のCaseを変更・再試験・PASS化しない。

| 本製品が担保すること | 必要な証拠の分担 |
| --- | --- |
| stream/ACPの受理・順序・ID・tool/permission/question/usageの正確な状態 | 実production parser/stateの既知入力・境界/race回帰と全対象データ。実transport/CLI版との代表接続は別に観察 |
| 日本語panel・input・Diff/permission・取消し・error表示 | regressionと代表nativeの実接続/表示/keyboard/accessibility。モデルの返答やcommand成功をUI成功にしない |
| EDT/background・dispose/generation・process所有と実停止 | 全故障/並行境界を決定的な回帰へ、IDE上の代表起動/終了・遅延結果抑止を実glueで確認。外部IDE/model内部の全組合せは保証にしない |
| 保存・復元・対象root・編集/実行の保全と権限 | 製品の保存契約/全必要内容・ID/順序・失敗/取消し・互換性を確認。metadata復元、本文replay、provider resume、Revertを混同しない |
| SDK/build/profile・ZIP/JARとロード実体 | 対象branchの標準build/互換性policy、固定source/ZIP/JAR/hash・実IDE/JBR/PID/profileの照合。別branch/外部製品のPASSを転記しない |
| AgentとAndroid IDE操作の正確な連携 | 呼出元/先・対象module/variant/device/run・permission・中止を検証。実端末固有の事実をfake/EMUから成功としない |

全データ・内容・保存・境界の検証と、代表nativeの相互運用は役割が異なる。既存の十分なfile/回帰/API/CLI・実render読取りを先に評価し、残る具体的なUI/OS/consumer保証だけを最小のGUIへ割り当てる。追加toolが必要なら公式能力/版/互換性と導入・保守負担を比較する。十分な既存経路を優先し、試すためだけに依存/host設定を増やさない。実tool/OS同意・lease・privacy・所有fixture・有限な上限/復旧はすべての方法で守る。

同じ候補/成果物/前提で各Caseの全条件を満たす観察は共有できる。新しい本文値やZIP名だけで全native操作を追加せず、関係する生成形式・導線・reader/runtime/display・設定/build/依存・失敗帰属を保証ごとに評価する。不明・変更の部分は新事実が必要。未知や製品failを根拠なく外部制約にしない。

方法の改訂・保持事実の現在評価・新しい実行は別に記録する。[正式な再利用境界](README.md#証拠の再利用と方法改訂)を使い、原観察と失敗、両source/artifact、実ロード/条件、全有効保証と独立評価を保つ。保証やCase集合を縮めず、方法だけの改訂で無関係な再build/再導入/全GUIを要求しない。計画改訂は製品受入の成功ではない。
