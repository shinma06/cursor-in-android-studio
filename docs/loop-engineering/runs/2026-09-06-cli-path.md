## 変更後の挙動

明示設定が空文字なら、実行時と同じ固定候補順で実行可能なCLIを探して入力欄に表示する。
画面に表示したパスと保存する上書き値を分け、表示だけ・通知変更のApplyで自動検出を手動固定しない。
手動指定はそのまま表示する。「自動検出に戻す」は候補を再検出して表示し、Apply/OK時に上書き値を空文字へ戻す。
手動パスを空欄にしてApplyした場合も再検出したパスを表示する。
Reset/Cancelでは未保存の選択を保存しない。固定候補がない場合はagentと表示し、実行時のPATH検索が未確認であると説明する。
設定の表示や検出でCLIを起動しない。AgentProcessServiceの不正パスfallback仕様は変更しない。

## GUI手順

予約取得後、対象HEAD/base、ZIP hash、ロードJAR、設定ディレクトリを識別する。
元のCLI上書き設定と通知設定を控える。使い捨てプロジェクトで実施し、CLIの送信は不要。

1. CLI設定を空欄でApplyする。検出されたパスが入力欄に現れ、「自動検出」の説明が出る。再表示してApplyが無効であることを確認する。
2. 通知設定だけを変更してApplyし、CLIが自動のままであることを確認する。通知設定を復元する。
3. 実在する通信なしfixtureのパスを手動入力してApply。再表示でも手動パスを表示する。
4. 「自動検出に戻す」を押すと通常CLIのパスに置き換わる。Cancelで閉じて再表示すると3の手動パスが保持される。
5. 再度「自動検出に戻す」→Apply/OK。再表示して自動パスと自動検出の説明を確認する。保存XMLの上書き値も空文字または省略を確認する。
6. 再び手動指定を保存し、入力欄を空欄にしてApply。自動パスが入力欄へ戻ることを確認する。
7. 元のCLI設定・通知設定へ復元し、未送信入力/処理/ダイアログが残っていないことを記録する。

固定候補なしの分岐は単体テストで検証し、実機のCLI削除/移動で再現しない。
